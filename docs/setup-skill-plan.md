# Setup skill: intent, full inventory, and upstream plan

## Intent

A setup skill in this repo (and, later, in [Scott Coffin's upstream repo](https://github.com/ScottCoffin/Job_Scraper)) that turns one sitting into a working scraper. The user brings their résumé, their LinkedIn profile, and [`docs/cv-to-config-prompt.md`](cv-to-config-prompt.md). The agent interviews them. When it finishes, job-scraper is ready to use: config written, secrets and variables set, the sources they chose turned on, the first runs done.

**It covers everything in the repo, not just what one fork uses.** That means every job source (including those in `.github/workflows/disabled/`) and every optional feature (phone alerts, weekly digest, AI fit-scoring, evals, upstream sync), each offered and either set up or explicitly skipped. `cv-to-config-prompt.md` is the interview and config-generation half; this file is the checklist the skill must cover and the pitfalls it must handle.

## What the skill must cover

### 1. GitHub (clicks the user or `gh` does)

- Fork with `main` only (`gh repo fork sahiltalwar88/job-scraper --default-branch-only`); Actions tab → "I understand my workflows, enable them" (forks start with scheduled workflows off).
- Settings → Actions → General → Workflow permissions → **Read and write** (workflows commit; the watchdog needs `actions: write`).
- Default branch must stay **`main`** (workflows fetch `origin main`; Pages deploys from it).
- Pages: deploy from branch `main`, folder `/`. Free Pages needs a public repo, which also makes `output/` public.
- Enable **Sync from upstream** in the Actions tab.
- Turn on each optional source or feature by moving its workflow from `.github/workflows/disabled/` to `.github/workflows/` (GitHub ignores subfolders).

### 2. Repository variables

| Variable | Needed for | Default / notes |
|---|---|---|
| `ENABLE_DATA_COMMITS` = `true` | **Required**: every data commit | Without it, scrapers run and save nothing |
| `DATA_BRANCH` | Where job data is committed | `main` (leave unset); the maintainer's repo uses `sahil-data` |
| `NOTIFY_MIN_FIT` | Phone alerts | 75. The config key `notify.min_fit` is **not read** |
| `WEEKLY_DIGEST_PUSHOVER` = `true` | Weekly digest | Or `notify.weekly_digest.enabled` in config |
| `WEEKLY_DIGEST_DAYS` | Weekly digest | 7 |
| `DASHBOARD_URL` | Weekly digest link | Derived from the repo otherwise |
| `JOBSPY_USER_AGENT` | Indeed, Glassdoor, ZipRecruiter, Google Jobs | Config `jobspy.user_agent` wins |
| `ENABLE_GLASSDOOR_WATCHER` = `true` | Glassdoor's **scheduled** runs | Manual runs always work |

### 3. Secrets

| Secret | Needed for | Notes |
|---|---|---|
| `CONFIG_JSON` | **Required** (this fork) | Single line, from `scripts/export-config-secret.sh`; multi-line breaks the backfill |
| `SCORING_PROFILE_JSON` | Résumé-scored phone alerts | `bash scripts/export-config-secret.sh scoring_profile.json`; overrides the committed file on runners |
| `PUSHOVER_TOKEN` + `PUSHOVER_USER` | Phone alerts, weekly digest | Both needed; test with **Test Pushover Notification** |
| `ANTHROPIC_API_KEY` | AI fit-scoring (`triage.yml`), evals | Without it `triage_agent.py` tries the local `claude` CLI |
| `CANDIDATE_PROFILE` | AI fit-scoring, evals | **Required** for both (`triage_agent.py` exits without it) |
| `CANDIDATE_RESUME` | AI fit-scoring, evals | Optional |
| `SERPAPI_API_KEY`, or `OXYLABS_USERNAME` + `OXYLABS_PASSWORD` | Google Jobs fallback | Only used when JobSpy returns nothing; config values win |
| `JOBSPY_PROXIES` | JobSpy boards | Config `jobspy.proxies` wins |
| `SYNC_TOKEN` | Upstream syncs that change workflow files | Fine-grained PAT: Contents + Workflows read/write |

No source needs a login: LinkedIn uses the public guest endpoint, USAJOBS the public site, the rest public HTML.

### 4. `config.json`

Generated by `cv-to-config-prompt.md`. Every key the code reads:

| Keys | Used by | Notes |
|---|---|---|
| `profile.title`, `.subtitle`, `.emoji` | Digest titles; dashboard | The dashboard gets it via `output/dashboard_config.json` |
| `keywords.include`, `.exclude` | Every source's title filter | Whole words; single words are word-bounded, so stems don't match |
| `keywords.fuzzy_seniority`, `.fuzzy_domain`, `.fuzzy_exclude` | LinkedIn title filter | Fuzzy mode only when seniority **and** domain are non-empty; it then replaces `keywords.include` |
| `search_terms.linkedin` | LinkedIn watcher, priority digest, backfill | **At most 8** (backfill matrix limit, below) |
| `search_terms.indeed` / `.glassdoor` / `.ziprecruiter` / `.google_jobs` / `.hiring_cafe` | JobSpy boards, HiringCafe | The last four fall back to Indeed's when `[]` |
| `search_terms.usajobs` / `.calcareers` / `.governmentjobs` | USAJOBS, CalCareers, NEOGOV | |
| `search_terms.workday` | Curated Workday employers | Inert: `CURATED_EMPLOYERS` in `scrape_jobs.py` is empty; enabling needs a code edit |
| `locations.linkedin` | LinkedIn watcher, priority digest | `{name, location, geoId}`; `geoId` may be `""` |
| `locations.linkedin_partitions.states`, `.high_volume.locations`, `.high_volume.day_slices` | LinkedIn backfill | High-volume `location` strings must match a `states` entry exactly (or be "United States"/"Remote") |
| `locations.indeed` / `.glassdoor` / `.ziprecruiter` / `.google_jobs` | JobSpy boards | `{location, country}`; the last three fall back to Indeed's |
| `location_filter.terms` | LinkedIn, NEOGOV, curated ATS | See the US-only pitfall |
| `google_jobs.queries`, `.serpapi_api_key`, `.oxylabs_*` | Google Jobs | Keep credentials empty; use secrets |
| `jobspy.proxies`, `.user_agent` | JobSpy boards | |
| `hiring_cafe.max_pages` | HiringCafe | Default 3 |
| `csucareers.max_pages` | CSU Careers | Default 30; missing from `config.example.json` |
| `employers.priority`, `.exclude` | Priority digest, fuzzy filter; exclusion everywhere | Loose substring match; names of 6+ characters |
| `priority_topics.terms` | Dashboard stars; phone alerts | `[label, regex]`; regex must work in Python **and** JS |
| `role_categories.terms` | Dashboard Role filter | Same regex rule |
| `sector_classification.terms` | Dashboard Sector filter | Regex over company names |
| `notify.weekly_digest.enabled`, `.days` | Weekly digest | Variables override |
| `triage.role_families` | AI fit-scoring | Pipe-separated; default `other` |

Not read: `notify.min_fit`, `locations.hiring_cafe`, `_README` and `_comment` keys.

### 5. `scoring_profile.json` (optional)

Read by `notify.py` (alerts) and the dashboard's Rank tab. Fields: `settings` (`title_multiplier` 3, `body_multiplier` 1, `score_multiplier` 1.6, `generic_cap`, `standout_threshold`), `fit_terms` (`{pattern, weight}`), `signature_terms` (regex strings), `poor_fit_terms` (`{pattern, penalty}`). This fork commits one with scoring turned off, because job-hunter does the grading; `SCORING_PROFILE_JSON` overrides it on runners.

### 6. Sources

| Source | Workflow | Needs |
|---|---|---|
| LinkedIn (hourly) | `linkedin_watch.yml` | `search_terms.linkedin`, `locations.linkedin`, keywords, `location_filter` |
| LinkedIn priority digest | `scrape_jobs.yml` | `employers.priority` |
| LinkedIn backfill | `linkedin_backfill.yml` | `locations.linkedin_partitions`; single-line `CONFIG_JSON` |
| Indeed, Glassdoor, ZipRecruiter, Google Jobs | `disabled/*_watch.yml` | `python-jobspy` (installed by the workflow); search terms and locations; optional proxies, user agent, Google fallback keys |
| HiringCafe | `disabled/hiringcafe_watch.yml` | Search terms (US-only public route) |
| USAJOBS | `disabled/usajobs_watch.yml` | `search_terms.usajobs`; no location filter (nationwide) |
| CalCareers, CSU Careers | `disabled/calcareers_watch.yml`, `csucareers_watch.yml` | Keywords; California only |
| NEOGOV + CalOpps | `disabled/localgov_watch.yml` | `search_terms.governmentjobs`, `location_filter`; CalOpps is California only |
| Curated Workday/Greenhouse | inside `scrape_jobs.yml` | Code edit (`CURATED_EMPLOYERS`) |

### 7. Features

- **Phone alerts**: Pushover secrets; `priority_topics`; optional `NOTIFY_MIN_FIT` and `SCORING_PROFILE_JSON`. Max 8 alerts per run.
- **Weekly digest**: move `weekly_digest.yml` out of `disabled/`; Pushover; `WEEKLY_DIGEST_PUSHOVER`.
- **AI fit-scoring**: move `triage.yml` out; `ANTHROPIC_API_KEY`, `CANDIDATE_PROFILE`, optional `CANDIDATE_RESUME`; `triage.role_families`. Writes `output/scores.json` for the dashboard.
- **Evals**: move `evals.yml` out; same secrets. Its golden cases (`eval_triage.py`) are written for one ML/health-data candidate and must be rewritten per user.
- **Upstream sync**: enable the workflow; `SYNC_TOKEN` recommended.
- **Dashboard**: Pages; branding and filters arrive through `output/dashboard_config.json`.

### 8. First runs

One at a time (they share the `job-scraper-commit-push` lock, and GitHub cancels a queued run when another queues): **Validate Setup** → **Clear Job Data** → **LinkedIn Backfill (Parallel)** → each enabled source with its backfill option → **Test Pushover Notification**. Then open the dashboard and spot-check the jobs.

## Pitfalls the skill must handle

- **Omitted keys inherit the example's search.** `config.json` is merged over `config.example.json` (the upstream author's toxicology search). Write every section; use `[]` for unused ones.
- **Backfill matrix limit.** GitHub allows 256 jobs per phase: Phase 1 = ⌈terms/2⌉ × (states + US-wide + Remote − high-volume); Phase 2 = ⌈terms/2⌉ × high-volume × 7. 8 terms, 50 states and 9 high-volume locations give 172 and 252.
- **US-only location filter.** `is_target_location()` always rejects a fixed list of non-US countries (Canada, UK, Australia, India, …). Non-US searches don't work for LinkedIn or NEOGOV.
- **Regexes run in two engines.** `priority_topics` is matched by Python (alerts) and JavaScript (dashboard): no inline flags, doubled backslashes in JSON.
- **Fork with `main` only.** This repo keeps its own data on a `sahil-data` branch; GitHub's Fork button copies only `main` by default, but `gh repo fork` copies every branch unless given `--default-branch-only`. If a fork has `sahil-data`, delete it.
- **Sync source.** Forks of this repo sync from it by default; `sync.upstream_repo` in `config.json` changes that (this repo's own config points at ScottCoffin/Job_Scraper).
- **`scripts/setup.sh`** sets `CONFIG_JSON` (asking for the config path) but not `SCORING_PROFILE_JSON`, and says to "enable" `triage.yml` when it must first be moved out of `disabled/`.
- **Scoring defaults differ**: with no profile settings, `notify.py` caps generic jobs at 35 while the dashboard uses 0, and they treat an empty `signature_terms` list differently.

## Porting to Scott Coffin's repo (next PR)

His `config.example.json` and `scoring_profile.example.json` are his real search: leave them as they are. His setup model differs from this fork's: users force-commit `config.json` to their fork, and only the parallel backfill reads `CONFIG_JSON`. Plan:

1. **The skill and prompt doc**, adapted to his model: all his sources are active (nothing in `disabled/`); config is committed (or `CONFIG_JSON` for the backfill, as his README's backfill section says after #5).
2. **`SCORING_PROFILE_JSON`**: his forks have no `scoring_profile.json`, so alerts are scored against his profile. Port the secret, the workflow step (only-when-set) and the export-script support.
3. **Dashboard config**: not needed while his forks commit `config.json`; port `output/dashboard_config.json` only if he moves to secret-only configs.
4. **Already sent**: #3 (sync), #4 (delta files), #5 (parallel backfill as the documented path, no example fallback).
5. **Check against his code** before porting anything: the pitfalls above (US-only filter, Clear Job Data gaps, scoring defaults, evals golden cases) come from this fork's code and may differ in his.
